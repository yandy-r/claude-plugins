# Release 5.1.1 — 2026-10-05

## Summary

Patch release. Adds `mods`, a new `ycc sync` intent that installs Claude Code mods from
`ycc/mods/`, seeded with a `status-bar` mod. Language rules no longer cite skills that
are not in the bundle, and a validator now keeps it that way. Also adds a Cursor Cloud
bootstrap. Versioned as a patch by explicit maintainer decision: the `mods` intent is
additive and opt-in, and no existing skill, command, or agent is added, renamed, or
removed.

## Added

a7b9779 feat(install): add mods sync intent with a status-bar mod

- `ycc/mods/`: a local `ycc-mods` marketplace for Claude Code mods (plugins whose
  `hooks/hooks.json` declares a `modules` entry that hooks into Claude Code itself). Needs
  Claude Code 2.1.287 or later.
- `ycc/mods/status-bar`: draws the context window above the prompt as a stacked bar, one
  color per `/context` category, with cost, rate limits and recent tool calls. Toggle with
  `/status-bar`.
- `ycc sync --target claude --intent mods`: registers `ycc/mods` as the `ycc-mods`
  marketplace and installs every mod it lists at user scope. Mods load in place from the
  checkout; run `/reload-plugins` after edits. It warns when a mod is also sideloaded via
  `CLAUDE_CODE_PLUGIN_DIRS`, which would load it twice.
- `cursor`, `codex` and `opencode` report the `mods` intent as unsupported and skip it.
- `scripts/validate-mods.sh` (`./scripts/validate.sh --only mods`), wired into
  `validate.sh`; a `MODS` row in the target capability matrix; `mods` added to the shell
  completions (bash, zsh, fish); install docs; and sync tests in
  `scripts/test-install-sync.sh`.

86e145c ci(cloud-agent): add Cursor Cloud dev environment bootstrap (#110)

- `.cursor/environment.json` and `.cursor/install.sh` for Cursor Cloud Agents. The script
  is idempotent and runs `npm ci` (dev deps and git hooks), installs `pyyaml`, `ruff`,
  `black` and `mypy`, and installs the pinned shellcheck via `scripts/install-shellcheck.sh`.

## Changed

- `validate.sh` runs a new `mods` section. `bundle-release` and the other release tooling
  are unchanged.

## Removed

None.

## Fixed

1fc24d5 fix(rules): resolve dangling skill references in language rules (#194)

- Rules under `ycc/rules/` cited skills that do not exist in the bundle (for example
  `golang-patterns`, `golang-testing`, `springboot-tdd`, `tdd-workflow`,
  `security-review`). Each is now either repointed to a real skill (`go-patterns`,
  `go-testing`, `code-review`, `frontend-design`, `frontend-patterns`) or dropped.
  Touches the C++, C#, Dart, Go, Java, Kotlin, Perl, PHP, Python, Rust, Swift, TypeScript
  and web rule sets plus `ycc/rules/README.md`; the generated Cursor rules follow.
- `scripts/validate-cursor-rules.sh` has a new "Skill references" check that fails when a
  rule names a skill with no `ycc/skills/<name>/SKILL.md`.

## Upgrade Notes

No action required. To try the new mod: `ycc sync --target claude --intent mods`. Other
`ycc sync` intents are unchanged. If you sideloaded a mod through `CLAUDE_CODE_PLUGIN_DIRS`,
remove it from `~/.claude/settings.json` once the marketplace copy is installed. Rule
files now reference only skills that exist, so references to `golang-patterns`,
`golang-testing` and similar names should be replaced by `go-patterns`, `go-testing` and
the other skills listed above.
