# Release 5.0.0 — 2026-09-30

## Summary

Major release. It adds a written branching and release model that ycc skills follow
automatically: a repo-root `RELEASING.md` with a machine-readable state block, the new
`ycc:release-model` and `ycc:backport` skills, and branch-aware `git-workflow`, `prp-pr`,
`releaser`, `code-review`, `git-cleanup`, `init` and `blueprint`. It also ships the
`install.sh` subcommand CLI (breaking: `install` is now a required subcommand), a `ycc`
command and shell completions, MCP scope/remove support, and opencode config fixes.

## Upgrade Notes

**Breaking — installer:** the bare form `./install.sh --target …` is rejected. Prefix it
with the `install` subcommand:

```bash
./install.sh install --target all --settings --rules --mcp --hooks
```

`sync`, `remove`, `cli` and `completion` are the other subcommands; `./install.sh cli`
puts a `ycc` command on your PATH.

**New — release model (opt-in per project):** nothing changes in a repository until it
has a `RELEASING.md`. To adopt the model, run `/ycc:release-model` in the project
(it proposes trunk-only or release-branches from the repo's history and never commits).
`/ycc:init` and `/ycc:blueprint` offer it during project setup. Then:

- `/ycc:git-workflow` and `/ycc:prp-pr` pick the PR base from `RELEASING.md`, refuse
  "sync main into X" PRs, and offer a `backport:X.Y` label on fixes.
- `/ycc:releaser` checks you release from the right branch (minors from the trunk,
  patches from `release/X.Y`) and creates `release/X.Y` on a new minor.
- `/ycc:backport <PR#>` (or `--pending`) cherry-picks merged fixes onto maintenance
  branches and opens the backport PRs.
