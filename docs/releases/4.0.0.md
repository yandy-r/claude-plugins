## Upgrade Notes

Two breaking changes require action. Both were flagged with `BREAKING CHANGE:`
footers in their commits.

### 1. `/ycc:releaser` — `--ci` renamed to `--ci-config`, `--ci` repurposed

The release-CI workflow generation/audit flag moved to `--ci-config`, freeing the
bare `--ci` namespace for a new bounded post-publish auto-fix loop (Phase 8.5).

| Before                      | After                              |
| --------------------------- | ---------------------------------- |
| `/ycc:releaser --ci=generate` | `/ycc:releaser --ci-config=generate` |
| `/ycc:releaser --ci=audit`    | `/ycc:releaser --ci-config=audit`    |

**This is a silent semantic change, not just a rename.** A stale
`/ycc:releaser --ci` invocation no longer errors — it now triggers the
post-publish auto-fix loop, which polls the release workflow run, dispatches a
`ycc:release-fix-applier` agent, and commits + pushes fixes. Audit any saved
aliases, scripts, or docs that pass `--ci` to `releaser` before upgrading.

The new loop runs only after a successful `--publish --confirm` and is bounded by
`--ci-max-pushes`, `--ci-max-same-failure`, and `--ci-timeout-min`. Its
non-destructive re-cut path requires `workflow_dispatch:` in your release
workflow; the audit checklist now flags a missing `workflow_dispatch:` as high
severity. The destructive `gh release delete --cleanup-tag` fallback is opt-in via
`--ci-recut=destructive`.

### 2. `/ycc:git-workflow` — explicit action flag now required

Bare `/ycc:git-workflow` no longer silently commits. It now prompts with a
numbered action menu. Pass an action flag to skip the prompt. The ladder is
cumulative and order-independent:

| Flag       | Effect                                    |
| ---------- | ----------------------------------------- |
| `--commit` | commit only                               |
| `--push`   | commit + push (implies `--commit`)        |
| `--pr`     | commit + push + PR (implies `--push`)     |

Modifier flags (`--dry-run`, `--no-docs`, `--draft`) keep their semantics;
`--draft` still requires `--pr`. Non-interactive callers that relied on bare
`/ycc:git-workflow` committing must now pass `--commit` explicitly, or they will
block on the menu prompt.

### No action required

All other changes are additive. New skills (`blueprint`, `pr-autofix`,
`visual-plan`, `visual-recap`), new agents (`pr-comment-fixer`,
`release-fix-applier`), and the `--enhanced` / `--visual` / `--ci` flags on
existing skills are opt-in.
